# Format Support Matrix

AI Timeline reads session files from AI coding tools and shows diagnostics. Each tool stores different data — here's exactly what you get from each one.

## Supported Formats

| Feature | Claude Code | OpenHands | SWE-Agent |
|---------|:-----------:|:---------:|:---------:|
| **File type** | `.jsonl` | `.jsonl` | `.traj` (JSON) |
| **Auto-detected** | Yes | Yes | Yes (by extension) |
| **Timestamps** | Per-event (ms precision) | Per-event (ms precision) | Synthetic (not stored) |
| **Tool call names** | Yes | Yes | Yes (parsed from action) |
| **Tool call arguments** | Yes (structured JSON) | Yes (structured JSON) | Partial (raw text parsed) |
| **Tool results** | Yes (full output) | Yes (full output) | Yes (full output) |
| **Tool call ↔ result linking** | Yes (via tool_use_id) | Yes (via action_id) | Yes (sequential pairing) |
| **Token usage (per-event)** | Yes (input, output, cache read, cache write) | No (accumulated only) | No (accumulated only) |
| **Token usage (total)** | Computed from per-event | Yes (from metrics) | Yes (from model_stats) |
| **Response latency** | Computed from timestamps | Yes (from response_latencies) | Not available |
| **Model name** | Per-event | Per-session | Per-session |
| **Thinking/reasoning** | Yes (thinking blocks) | Yes (thought field) | Yes (thought field) |
| **Session ID** | Yes | Instance ID | Instance ID |
| **Working directory** | Yes | No | No |
| **Git branch** | Yes | No | No |
| **Error detection** | Yes (is_error flag) | Yes (is_error flag) | Heuristic (Error/Traceback in output) |
| **Cost tracking** | No | Yes (accumulated_cost) | Yes (instance_cost) |
| **Sub-agent sessions** | Yes (separate .jsonl files) | No | No |
| **Multiple instances per file** | No (one session per file) | Yes (one per line) | No (one per file) |

## Where to Find the Files

### Claude Code
```
~/.claude/projects/<project-slug>/<session-id>.jsonl
~/.claude/projects/<project-slug>/<session-id>/subagents/*.jsonl
```
Every Claude Code session creates these automatically. No configuration needed.

### OpenHands
```
benchmarks/results/<run>/<dataset>/<model>/output.jsonl
```
Generated by OpenHands evaluation harness. Each line is one complete instance with full history.

### SWE-Agent
```
trajectories/<run>/<instance-id>.traj
```
Generated by SWE-Agent runs. Each `.traj` file is one instance.

## What Works with Local Models

If you're running local models (via vLLM, Ollama, LM Studio, etc.) through these tools, the trajectory files are generated the same way. The viewer doesn't care what model ran — it just reads the files.

| Tool | Local model support | What changes |
|------|:-------------------:|--------------|
| **Claude Code** | Not directly (uses Anthropic API) | Use with Anthropic-compatible proxy |
| **OpenHands** | Yes (any OpenAI-compatible endpoint) | Model name in metrics reflects your local model |
| **SWE-Agent** | Yes (any OpenAI-compatible endpoint) | Model name in info.model reflects your local model |
| **Continue.dev** | Yes | Parser included (test fixtures only so far) |
| **Cline** | Yes | Parser included (test fixtures only so far) |
| **Aider** | Yes | *Parser coming soon — lossy format, no structured tool calls* |

## Feature Availability by Data Quality

### Full analytics (timeline, per-tool stats, token breakdown)
- **Claude Code** — best data quality. Per-event tokens, precise timestamps, structured tool calls.

### Good analytics (timeline, tool stats, total tokens)
- **OpenHands** — per-event timestamps, structured actions/observations, total token counts + per-response latency.

### Basic analytics (timeline, tool stats)
- **SWE-Agent** — no real timestamps (generated sequentially), total token counts from model_stats, action text parsed into tool names.

## Adding New Formats

Each parser is ~50-100 lines of TypeScript that implements `TrajectoryParser`:

```typescript
interface TrajectoryParser {
  canParse(filename: string, firstLine?: string): boolean;
  parse(contents: string, filename: string): Trajectory[];
}
```

To add support for a new tool:
1. Create `src/parsers/<tool-name>.ts`
2. Implement the two methods — map the tool's format to `TrajectoryEvent[]`
3. Register it in `src/parsers/index.ts`
4. Add test fixtures and tests in `tests/`

Community contributions welcome — if your favorite tool stores session data locally, we can probably parse it.
